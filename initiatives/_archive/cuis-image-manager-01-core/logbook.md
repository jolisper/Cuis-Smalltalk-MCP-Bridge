## Phase 2 — [Scaffold] Copy-on-write Packages probe

Verdict: copy-on-write holds. In a scratch directory outside the repo, the pinned Cuis 7.8 archive was downloaded and its checksum verified against the pin. Two instances were built with real Packages directories holding one absolute symlink per shared file. Instance A required JSON, compiled a method and saved the package. Cuis 7.8 saves by force-creating a new file at the path it loaded from, so only the instance symlink was replaced by a regular file containing the method. The shared file kept the same checksum, inode and modification time, and instance B kept its symlink and loaded JSON without the method. Side effect worth knowing: saving bumps the package revision, so the instance copy then differs from the shared one in version as well as content. No fallback to per-instance copies is needed, and nothing was written to the repo.
